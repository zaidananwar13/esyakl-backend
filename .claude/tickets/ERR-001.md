# Ticket ERR-001: Fix Project Submission (Proyek Akhir) Compatibility & Validation

## Ticket Information
- **Ticket ID**: ERR-001
- **Module / Feature**: Proyek Akhir (Final Project Submission) API (`/api/project/submit`)
- **Status**: Resolved
- **Date**: 2026-11-16

---

## Issue Description
Users encountered submission failures when submitting Proyek Akhir via `/api/project/submit`:
1. **Response Contract Mismatch**: Legacy frontend clients inspect `response.data.status` (e.g. `status === 200`) to confirm success. The backend was returning standard new envelopes (`code` without `status`), causing frontend submission handlers to treat successful uploads as failures.
2. **Project Lookup Inflexibility**: The submission parameter `project` was treated strictly as `id_class`. If the client sent `id_project` (e.g. from the project details view), the query failed to find the project or enrollment, returning 404 "Class enrollment not found or expired".
3. **Enrollment Expiration Blocking Completed Students**: The enrollment verification strictly enforced `expired_at >= now()`. Students who had completed the course (`completed_at` is set) but whose class access duration expired were erroneously blocked from submitting their final project.
4. **PDF Variant MIME Type Rejection**: Uploaded PDF files with variant MIME types (such as `application/x-pdf`, `application/acrobat`, `applications/vnd.pdf`) were rejected with 422 "Invalid file type" or 401 validation errors.

---

## Root Cause Analysis
1. **Response Format**: `ProjectController::submit()` was using `successResponse()` and `errorResponse()`. In `ApiResponseTrait`, these envelopes include `'code'`, `'message'`, and `'data'`, but omit `'status'`. The legacy frontend expects `{status: 200, message: ...}` on success and `{status: <code>, message: ...}` on error.
2. **Lookup Logic**: In `ProjectService::submitProject()`, the input was directly used in `ClassStudent::where('id_class', $projectClassId)` and `Project::where('id_class', $projectClassId)`. There was no resolution logic to check if the input corresponded to `id_project` instead of `id_class`.
3. **Enrollment Check**: The query in `submitProject()` required `expired_at >= Carbon::now()->format('U')`, without checking `completed_at`. Under course business rules, completed students retain project submission privileges.
4. **File Validation**: `ProjectService::validateProjectFile()` checked `$file->getMimeType()` against `$allowedMimes`, which only included standard `application/pdf`. Additionally, in `ProjectController::submit()`, the validator rule `mimes:zip,rar,pdf,docx,txt` relied on Symfony's default extension guesser which does not map `applications/vnd.pdf`.

---

## Detailed List of Changes Made

### 1. `app/Http/Controllers/API/ProjectController.php`
- **Response Contract**:
  - Success responses now return `$this->legacyResponse(self::API_NAME, ['status' => 200, 'message' => $result['message']], 200)`.
  - Error responses from service now return `$this->legacyResponse(self::API_NAME, ['status' => $result['code'], 'message' => $result['message']], $result['code'])`.
- **Validation Logic**:
  - Updated `project_file` validation to support PDF variant MIME types (`application/pdf`, `application/x-pdf`, `application/acrobat`, `applications/vnd.pdf`) and RAR MIME types (`application/x-rar`, `application/rar`, `application/x-rar-compressed`, `application/vnd.rar`) in addition to ZIP, DOCX, DOC, and TXT files.
  - Added dual MIME validation checking both detected server MIME (`$value->getMimeType()`) and client-reported MIME (`$value->getClientMimeType()`) to prevent false rejections. Enforced 12MB limit.

### 2. `app/Services/ProjectService.php`
- **Parameter Typing & Lookup Resolution**:
  - Updated `submitProject()` to accept `int|string $projectIdOrClassId`.
  - Implemented flexible lookup checking both `id_project` and `id_class`. If an overlap occurs and user is enrolled in both, prioritizes `id_class` to maintain backwards compatibility with legacy frontend clients.
- **Enrollment Verification**:
  - Updated enrollment check to verify `expired_at >= now` OR `completed_at > 0`.
- **MIME Types**:
  - Added `application/x-pdf`, `application/acrobat`, `applications/vnd.pdf`, `application/x-rar`, and `application/rar` to `$allowedMimes` in `validateProjectFile()`.
  - Added client MIME check fallback via `getClientMimeType()`.
- **Execution Order & Activity Logging**:
  - Deferred writing the uploaded file to disk until after project and enrollment validations pass.
  - Corrected `Helper::recordUserActivity()` to pass the resolved class ID (`$projectModel->id_class`).
