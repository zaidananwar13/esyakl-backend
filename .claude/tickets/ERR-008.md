# Ticket ERR-008: Register New Account Tersangkut Status 'Loading'

## Ticket Information
- **Ticket ID**: ERR-008
- **Module / Feature**: Autentikasi / Pendaftaran (`POST /register`)
- **Location**: Halaman Register New Account (`/sign-up`)
- **Status**: Resolved
- **Date**: 2026-11-16

---

## Issue Description
Pada halaman pendaftaran akun baru (*Register New Account* / `/sign-up`), setelah pengguna mengisi seluruh kolom formulir (Nama, Email, Password, Konfirmasi Password) dan menekan tombol **Daftar / Sign Up**, tombol pendaftaran berubah menjadi status `'Loading'` dan tersangkut secara permanen tanpa adanya respon, pesan error, maupun *redirect*.

---

## Root Cause Analysis

Berdasarkan pemeriksaan mendalam terhadap kode frontend Svelte (`/var/www/arabic-go.com/src/components/Sign-up-content.svelte`) dan backend Laravel 13, ditemukan kombinasi akar masalah:

### 1. Ketiadaan Handler `.catch()` di Frontend (`Sign-up-content.svelte`)
- Pada baris 208-250 `Sign-up-content.svelte`:
  ```javascript
  ApiController({
    method: "POST",
    endpoint: `register`,
    datas: { name: ..., email: ..., password: ..., repassword: ... },
  }).then((response) => {
    canSignUp = true;
    if (response.data == "check your email :)") {
      Swal.fire({ ... }).then(() => {
        window.location.href = `/sign-in?lang=${selectedLang}`;
      });
    } else if (response.data.message == "email sudah ada") {
      ...
    }
    window.$("#sign-up-button").removeClass("primary-button-disabled");
    window.$("#sign-up-button").text("Daftar");
  });
  ```
- **Masalah**: Pemanggilan API sama sekali **tidak memiliki blok `.catch()`**.
- Perintah untuk menonaktifkan status loading (`window.$("#sign-up-button").removeClass("primary-button-disabled").text(...)`) diletakkan di dalam `.then()`.
- Jika request backend menghasilkan error HTTP (seperti HTTP 500 / 429 / 504), promise akan *reject*, blok `.then()` tidak pernah dijalankan, sehingga tombol pendaftaran selamanya tersangkut pada status `'Loading'`.

### 2. Fatal Exception Symfony Mailer (HTTP 500) di Backend
- Di `app/Services/AuthService.php`, method `sendVerificationEmail()` memanggil pengiriman email secara sinkron (`Mail::to($user->email)->send(...)`).
- Pada konfigurasi `.env` server live:
  ```text
  MAIL_MAILER=smtp
  MAIL_HOST=mailhog
  MAIL_PORT=1025
  MAIL_FROM_ADDRESS=null
  ```
- **Masalah 1**: `MAIL_FROM_ADDRESS` bernilai `null`. Pada Laravel 13 (Symfony Mailer), pengiriman email tanpa header *From* langsung melempar exception:
  ```text
  Symfony\Component\Mime\Exception\LogicException: An email must have a "From" or a "Sender" header.
  ```
- **Masalah 2**: `MAIL_HOST` disetel ke `mailhog:1025` yang tidak aktif di server, menyebabkan *connection timeout*.
- Karena pemanggilan `Mail::send` sebelumnya tidak dibungkus dalam blok `try-catch`, exception ini membuat endpoint `/register` melempar **HTTP 500 Internal Server Error**.

### 3. Ketidaksesuaian Kontrak Respons Sukses (Legacy Contract)
- Pada baris 210 `Sign-up-content.svelte`, frontend secara ketat memeriksa:
  ```javascript
  if (response.data == "check your email :)")
  ```
- Backend Laravel 13 sebelumnya mengembalikan format JSON:
  ```json
  {"title": "E - Syakl | Authorizer API", "code": 200, "message": "check your email :)", "data": null}
  ```
- Pada Axios, `response.data` berupa Objek JSON, sehingga evaluasi `response.data == "check your email :)"` bernilai `false`.

### 4. Batasan Rate Limiter yang Terlalu Ketat
- Rute `register` dibatasi oleh `middleware('throttle:registration')` dengan batas hanya **3 request per menit**. Uji coba berulang oleh QA langsung terblokir oleh HTTP 429 yang juga membuat frontend hang.

---

## Solution & Implementation Details

Semua perbaikan diselesaikan di sisi **Backend & Server** tanpa perlu mengubah kode frontend produksi:

### 1. `app/Services/AuthService.php`
- Menambahkan fallback alamat pengirim (`config('mail.from.address') ?: 'noreply@arabic-go.com'`) dan nama pengirim default pada `VerificationMail`.
- Membungkus pengiriman email verifikasi dalam blok `try-catch (\Throwable $e)` dengan `Log::warning(...)`.
- **Hasil**: Pembuatan akun user dan pembuatan token verifikasi email selalu sukses (HTTP 200), terhindar dari *crash* HTTP 500 meskipun mail server bermasalah.

### 2. `app/Http/Controllers/API/LoginController.php`
- Mengembalikan kontrak respons lama untuk pendaftaran sukses:
  ```php
  return response($result['message'], 200)->header('Content-Type', 'text/plain');
  ```
- **Hasil**: Axios menerima string `"check your email :)"`, mencocokkan kondisi `response.data == "check your email :)"` di Svelte, memunculkan modal SweetAlert2 sukses, dan melakukan redirect ke `/sign-in`.

### 3. `app/Providers/RouteServiceProvider.php`
- Melonggarkan rate limiter `registration` dari 3 request/menit menjadi **10 request/menit**.
