# Ticket ERR-009: PHPUnit Test Suite Failures Post-Security Hardening

## Ticket Information
- **Ticket ID**: ERR-009
- **Module / Feature**: Backend Testing / PHPUnit Test Suite
- **Location**: `tests/Feature/ExampleTest.php`, `tests/Unit/Controllers/`, `tests/Unit/Services/`
- **Status**: Open / Backlogged
- **Date Created**: 2026-11-18
- **Severity**: Medium

---

## Issue Description
Setelah proses refactoring dan security hardening di Laravel 13, eksekusi test suite `vendor/bin/phpunit` menghasilkan **9 Failures** dan **2 Risky tests** dari total 315 tests.

Implementasi production code berjalan dengan benar dan lebih aman, tetapi file test unit/feature belum diselaraskan dengan aturan keamanan dan spesifikasi REST baru.

---

## Detailed Root Causes & Fixes

### 1. `tests/Feature/ExampleTest.php`
- **Error**: `Expected response status code [200] but received 404.`
- **Penyebab**: Route `routes/web.php` didaftarkan dengan prefix `web` di `RouteServiceProvider`. Endpoint `GET /` tidak ada, yang ada adalah `GET /web`.
- **Rencana Perbaikan**:
  ```php
  public function test_example()
  {
      $response = $this->get('/web');
      $response->assertStatus(200);
  }
  ```

### 2. `tests/Unit/Controllers/PaymentControllerTest.php`
- **Error**: `Failed asserting that 422 matches expected 401.` pada `test_create_snap_payment_returns_unauthorized_when_no_user`.
- **Penyebab**: `PaymentController::createSnapPayment` melakukan validasi parameter `class` (`required|integer|exists:class,id_class`) sebelum memvalidasi autentikasi token pengguna. Test mengirim request kosong tanpa parameter `class`.
- **Rencana Perbaikan**:
  Ubah test untuk menyertakan input `class` dummy atau ubah urutan pengecekan autentikasi terlebih dahulu sebelum validasi payload.

### 3. `tests/Unit/Services/PromoServiceTest.php`
- **Error**:
  1. `test_validate_promo_code_returns_error_when_not_found`: Actual `404`, Expected `401`.
  2. `test_get_promo_details_returns_error_when_code_is_null`: Actual `400`, Expected `401`.
  3. `test_get_promo_details_returns_error_when_not_found`: Actual `404`, Expected `401`.
- **Penyebab**: `PromoService` direfaktor menggunakan status code REST standar:
  - Kode tidak ada = `404 Not Found`
  - Kode kosong/null = `400 Bad Request`
  Test lama masih mengasumsikan kode error warisan `401 Unauthorized`.
- **Rencana Perbaikan**:
  Perbarui asersi pada `PromoServiceTest.php` untuk memvalidasi kode status 404 dan 400.

### 4. `tests/Unit/Controllers/QuizControllerTest.php`
- **Error**:
  - `test_freekey_returns_success`: Actual `403`, Expected `200`.
  - `test_freekey_with_null_syllabus_from_request`: Actual `403`, Expected `200`.
  - 2 Risky tests: handler tidak di-reset.
- **Penyebab**: Endpoint `freekey` yang membocorkan kunci jawaban kuis telah dikunci dengan proteksi role `admin` (`if (!$user || $user->type !== 'admin') return 403;`). Test memanggil endpoint tanpa autentikasi user admin.
- **Rencana Perbaikan**:
  Mock user dengan atribut `type => 'admin'` dan `api_token` valid dalam test case.

### 5. `tests/Unit/Services/UserServiceTest.php`
- **Error**:
  - `update_password_returns_error_when_password_too_short`: Asersi teks error mencari `'password length'`, pesan aktual adalah `'Password must be at least 8 characters long'`.
  - `update_password_validates_minimum_length_boundary`: Password 6 karakter (`123456`) diharapkan lolos validasi, namun sekarang mengembalikan 422.
- **Penyebab**: Batas minimum panjang password dinaikkan dari 6 menjadi 8 karakter demi kepatuhan keamanan.
- **Rencana Perbaikan**:
  Perbarui pengujian boundary pada `UserServiceTest.php` menjadi 8 karakter (`12345678`).
